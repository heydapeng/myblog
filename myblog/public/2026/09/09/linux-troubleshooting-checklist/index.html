Linux 排障备忘：从进程、端口到日志

  • Linux 

接口超时后，立即重启可能恢复服务，也可能丢掉最有用的现场。这里整理一组只读检查，适用于常见 Linux 服务环境。

先确认进程与端口

核对启动命令和监听地址。进程存在不等于应用就绪；监听在 127.0.0.1 的服务也不能直接从其他机器访问。查看其他用户的进程信息可能需要相应权限。

再看资源

负载升高后继续判断是 CPU 忙还是任务在等待，不能把负载值直接当作 CPU 使用率。磁盘除了容量，也要看 inode，许多小文件同样可能让写入失败。

用时间串起日志

在使用 systemd 的机器上，把下方 your-service 换成实际单元名：

若应用写文件日志，就改查对应文件。围绕报错时间查首次异常、依赖连接失败以及近期配置变化，不只搜索最后一条超时信息。命令细节以当前机器的 man journalctl 为准。

留下可复查的记录

建议记录“发生时间、影响范围、观察到的事实、采取的动作、恢复依据”。例如端口没有监听是事实；“可能是数据库连接阻塞启动”是待验证的假设。把两者分开，后续复盘会清楚很多。
