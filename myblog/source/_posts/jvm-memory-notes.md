看到内存相关异常时，先别急着增大堆。先判断是哪一块运行时区域出了问题，再看对象、调用深度或资源生命周期。

<!-- more -->

## 两条线索

JVM 规范把堆与方法区定义为线程共享区域；程序计数器、Java 虚拟机栈属于线程私有区域。一次方法调用会创建栈帧，保存局部变量、操作数栈等信息。局部变量可以持有引用，但引用和它指向的对象不是同一回事。详见 [JVM 运行时数据区规范](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.5)。

## 用一个调用理解它

```java
int lengthOf(String value) {
    String normalized = value.trim();
    return normalized.length();
}
```

这里先约定 `value` 非空。调用过程中，栈帧保存参数和局部引用；不能据此说字符串对象也存放在栈帧里。实际执行还可能经过优化，因此概念模型不等于物理内存布局。

## 异常是线索，不是结论

排查时可以先记录完整异常、出现时间、流量变化与近期发布。若调用栈反复出现同一个方法，检查递归的终止条件；若业务集合持续增长，检查是否缺少淘汰策略。

不要只看进程内存上涨就认定 Java 堆泄漏。下一步应结合当前 JDK 的诊断工具与运行参数，区分堆、线程和其他进程内存来源，再设计验证。
